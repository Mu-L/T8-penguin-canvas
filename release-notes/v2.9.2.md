# T8 Penguin Canvas v2.9.2

本版集中优化 Electron 启动、画布目录、单画布加载、主题与媒体资源调度，并补齐跨画布后台运行的持久化安全边界。既有节点、模型、默认渠道、用户画布、工作流、Provider 协议以及 v2.9.1 和更早版本的全部能力保持不变。

## 启动与目录

- Electron 先显示可操作启动壳；主界面加载成功且 `ready-to-show` 后替换，15 秒有界兜底会显示重新加载画布和打开本地后端入口。
- 后端导入、`/api/status` 与前端壳不再同步打开项目数据库或协作 Gateway；数据库备份、语义刷新、运行恢复与 Figma Bridge 延后并受关机 fence 约束。
- 画布目录首屏按 50 项游标分页，侧栏采用窗口化渲染；损坏或缺失索引以小批次渐进恢复，请求热路径不回退到全库正文扫描。
- 保存后只定点刷新目标画布元数据；重命名先提交 SQLite 权威数据，兼容镜像故障不会把已提交结果误报为失败。

## 画布、主题与媒体

- 单画布只执行一次 canonical hydration；权威 GET 失败或超时时保持只读、显示重试且不会发送空画布 PUT，取得有效 revision 后才恢复写权限。
- 视口按画布写入本地 LRU；旧画布只在没有有效保存视口时执行一次 fit，快速切换前会冲刷待保存编辑。
- 主题 CSS 和大型主题体验按需加载并双缓冲切换；加载失败回退 tech，避免半主题与首屏外网字体阻塞。
- 图片、视频、音频共用单例可见性观察器和 4/1/1 并发调度；离屏资源不抢首屏，首次点击播放会保留用户意图。

## 跨画布后台运行安全

- 运行以 `canvasId + entityUid` 绑定原始画布实体，即使 A/B 画布出现相同可见 nodeId，也不会互相串写。
- 后台结果通过 revision CAS 的 `node.patch` 提交；冲突只重新读取并确认同一实体后有界重试，不用全量画布覆盖用户并发编辑。
- 已完成提交进入有界 mailbox，原画布重新挂载后按 revision 合并；节点已删除或同 ID 重建时不会被旧结果复活。
- 权威后台 patch 会使旧 autosave 代次失效；迟到的 409 不会污染已 rebase 的新 pending，也不会造成未处理 Promise 拒绝。
