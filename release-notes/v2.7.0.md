# T8 Penguin Canvas v2.7.0

本版重点不是再增加一层 Agent 外壳，而是让 Creator Agent 真正参与创作，并从根因修复完成任务在代理、TUN、VPN 或 IPv6 环境变化后无法取回结果的问题。

## Creator Agent 实用化

- Creator Agent 接入真实在线语言模型流式运行时。用户给一句目标或上传参考素材后，先获得可编辑的故事、TVC、电商、图像、视频或音频工作稿，不再只收到问卷、泛化复述或循环标签。
- 图像、视频和音频附件会作为持久化创作证据参与模型决策；没有完成视觉或音频理解时，Agent 不会声称已经分析素材。
- 每轮三个建议从本轮实际工作稿、当前创作阶段和可执行能力生成，点击后继续推进同一个作品；新对话不会继承旧会话的阶段、动作或附件。
- 主对话保持简洁的大字号流式创作体验，技术回执、运行证据和内部任务不再占据聊天主体。
- 新增版本化创作工件和高层工具提案。任何画布写入、节点运行或交付仍需公开能力目录、预览、审批、revision 新鲜度与持久证据，内部路由、凭据、数据库和原始 CanvasPatch 不对 Agent 开放。

## 生成结果与网络恢复

- 修复连接池在代理、TUN、VPN 或 IPv6 状态变化后复用失效连接的根因；新的查询与下载会建立新连接。
- IPv6 优先连接失败时自动回退 IPv4，同时保留纯 IPv6 网络支持。
- 已完成的图像、视频、音频、3D 和 RunningHub 任务只重新查询并下载原任务结果，不会因为网络错误重新提交生成或重复扣费。
- TUN Fake-IP、当前系统代理和公网 DNS/DoH 回源使用同一套有界、安全下载链路；同一任务的并发轮询会合并，避免重复保存。
- 只有结果完成下载、校验、持久化并关联原 Run/NodeRun 后才向节点报告完成；失败时返回可定位、但不泄露签名 URL 或凭据的真实原因。

## Agent、CLI 与 Skill 一致性

- Creator Agent、Agent Control、zcanvas CLI 和打包内 Codex Skill 继续由同一能力图、模型目录和权限合同生成。
- 新增创作能力会同步进入公开能力清单和 zcanvas 运行目录，避免画布、CLI 与本地 Agent 各自维护一套易漂移的定义。

## 发布边界

- 本次 Electron/NSIS 正式打包只执行一次，使用 BelowNormal 优先级和受限逻辑核心；不运行 FFmpeg 转码或额外 Electron 冷启动压力测试。
- 用户已明确授权先发布、后补真实 Provider、协作多端与安装升级证据；延期不会把尚未执行的证据标记为通过。
