# T8 Penguin Canvas v2.8.2

本版修复部分 Windows 用户在中文账户名、中文 userData、安装目录或素材文件名环境下调用图像等 Provider 节点时，Electron 主进程出现 `ByteString` / `Headers.set` 未捕获异常的问题。v2.8.1 及更早版本的节点、模型、工作流、渠道默认值和系统网络能力保持不变。

## Windows 中文用户名与路径兼容

- 根因是 Electron 33 的主进程 `session.fetch` 响应适配：Chromium 可把服务端响应头中的 UTF-8 文件名或路径暴露为 Unicode JavaScript 字符串，Electron 随后复制到 Undici `Headers` 时因 WebIDL `ByteString` 只接受 0–255 码点而崩溃。
- 共享 Chromium 系统网络桥只对无 WebContents 的主进程 `session.fetch` / `net.fetch` Unicode 响应头执行可逆的 UTF-8 字节保留映射；ASCII/latin1 响应头和渲染器请求完全不变。
- 请求 URL、真实 Windows 文件路径、请求正文、响应正文与 Provider 载荷不做编码替换；中文 `%APPDATA%` / userData、中文输入目录、中文图片名的本地读取、Seedream I2I Base64 转换及输出保存继续使用原生 Unicode 路径。
- 保留 Chromium 系统代理、PAC、TUN、VPN、IPv4/IPv6 路径和现有恢复策略；不会回退到通用 Node 网络栈，也不会为模糊失败自动重放付费写请求。

## 验证与发布边界

- 真实 Electron 33 对照进程在关闭兼容层时稳定复现用户截图中的 `Headers.set` / `ClientRequest` 栈及字符 `自`（33258），启用后同一中文 `Content-Disposition` 返回 HTTP 200，正文和原始 UTF-8 路径字节均可恢复。
- 系统网络桥、Electron 集成、打包 userData 路径和 Seedream 中文本地素材链定向回归 23/23 通过；TypeScript、能力同步、公开源码检查、RH 工具箱清单和生产构建纳入固定发布提交门禁。
- 反馈用户安装环境、协作多端和安装升级证据按用户授权在发布后补录；延期不会被标记为已通过。
- Electron/NSIS、私有后端加密、运行时归档、post-build、provenance、sealed recovery、自动更新三项资产、固定 Tag 与 Latest 由固定 source commit 上的唯一正式发布流程生成并核验。
