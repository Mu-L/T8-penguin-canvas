# 贞贞的无限画布 v2.5.8

本版完成多人协作、审片及公网加固路线的第 1 轮，重点补齐独立协作网关、画布资源授权、邀请、角色/能力、只读连接和主机管理。

## 协作主机

- Workbench 新增“协作主机”面板，可选择具体 IPv4 网卡与端口，并展示局域网访问地址。
- 分享二维码完全在本机生成，不会把邀请链接上传到第三方二维码服务。
- 可设置邀请角色、有效期和最大使用次数，并支持撤销邀请。
- 可调整成员角色、移除成员、撤销单个会话、断开全部会话和停止网关；高影响操作均要求明确二次确认。
- 管理接口只接受本机回环访问；公开监听只暴露协作路由，不会顺带开放私有后端、设置或 API Key。

## 邀请、权限与会话

- 邀请严格绑定项目与画布，并在兑换时重新核验当前画布的资源范围。
- viewer 保持只读，reviewer 只获得审阅能力，editor/owner 才能按实际能力写入、运行或发布。
- 成员角色变化会使旧 WebSocket 能力立即失效；撤销单会话、全部会话或关闭网关也会主动断开已有连接。
- 运行意图重新绑定成员、项目、画布和 `runWorkflow` 能力，不能跨画布复用旧身份。

## 画布资源边界

- SQLite schema 23 为协作画布建立持久资源授权，覆盖 AssetRef、画布 URL 映射和固定子工作流依赖。
- 画布文档、增量同步、历史操作、Patch、重复提交与邀请兑换统一复核资源范围。
- 缺失 canonical、同 id/version 内容摘要冲突、未授权历史引用和 revision 缺口会失败关闭或回退到权威快照。
- 旧 JSON 画布首次读取只建立未初始化状态，必须由主机明确确认资源范围后才能创建邀请。
- Project AssetRef 与视频编辑时间线内部 `assetId` 使用不同命名空间；无 version 的子工作流草稿根 `assetRefs` 也会在发布前校验。
- 发布子工作流时会校验新根定义及全部固定依赖，不会拿旧 canonical 错误比较新草稿内容；本机发布和导入事件只通知持有精确固定版本授权的画布。
