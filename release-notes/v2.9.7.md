# T8 Penguin Canvas v2.9.7

本版修复部分用户从 v2.9.1 更新到 v2.9.2–v2.9.6 后，画布项目在再次启动时可能出现“项目数据库 typed canonical JSON 不变量校验失败”的问题。修复保持启动只读、历史数据兼容范围精确，并继续拒绝非匹配的数据库损坏。

## 修复

- 根因是 v2.9.2 起的画布目录重命名路径更新了 SQL `canvas_documents.updated_at`，却只把 `name` 与 `nodeCount` 写回 `snapshot_json`，遗漏同步 JSON `updatedAt`。
- 今后的目录元数据写入使用同一个时间值同时更新 SQL 行和画布 JSON，确保冷启动 typed canonical 校验一致。
- v2.9.2–v2.9.6 已产生的旧漂移只在精确签名下兼容：SQL 时间严格晚于合法 JSON 时间、目录名合法非空，并且 `nodeCount` 精确等于 `nodes.length`。
- 兼容路径不会在启动时静默改写用户项目数据库；运行时继续以 SQL 行时间为权威值，下一次真实写入才自然保存 canonical JSON。
- 其他时间异常、节点数量不一致、schema/身份/revision 损坏仍按原安全策略失败关闭。

## 验证

- 新目录重命名会同时保存 JSON `updatedAt` 与 SQL `updated_at`，并可冷重开。
- 精确复现 v2.9.2–v2.9.6 历史漂移后可只读冷重开，且存储的 JSON 不会在启动期间被改写。
- 构造同类时间漂移但篡改 `nodeCount` 时仍触发 typed canonical 错误，证明兼容范围没有扩大为通用绕过。
- 测试数据库只在系统临时目录创建并于测试结束后清理；没有读取、复制或修改用户保留项目数据库。

## 完整保留

- v2.9.6 的 FlashVSR 名称修正、v2.9.5 Seedance 2.5 `native1080p`、v2.9.3 MiniMax Music3、全部 79 个节点、默认渠道、默认模型、旧画布与既有工作流均不回退。
