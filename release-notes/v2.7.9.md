# T8 Penguin Canvas v2.7.9

本版新增独立 Seedance 2.0 提示词增强器，并修复部分用户在 Electron 系统代理、TUN 或 VPN 环境中查询和运行自定义 RunningHub WebApp 时出现的 `net::ERR_INVALID_ARGUMENT`。

## Seedance 2.0 提示词增强器

- 新增独立 `seedance20-prompt-enhancer` 节点，与 MiniMax H3 协议隔离，接受文本、图片和完整视频输入，输出可继续连接下游的文本提示词。
- 覆盖 AUTO、文生视频、图生视频、首尾帧、多参考、视频编辑、视频延长、轨道补齐和组合任务，支持 AUTO/4–15 秒、AUTO/1–20 镜头、简单/复杂分镜、严格/均衡/创意改写、双引用语法、字幕和稳定性策略。
- 默认渠道仍为“贞贞的平价AI小屋”，默认模型仍为 `bytedance/doubao-seed-2.1-pro`；贞贞工坊与全部已启用的扩展 LLM Provider 可显式选择，失效 Provider 或模型不会静默回退。
- 图片最多 9 张、视频最多 3 个、媒体合计最多 12 项；节点不接受音频，也不会声称分析音频。API Key 继续只由全局设置管理，每次正式增强只提交一次 LLM 请求。

## RunningHub Chromium 网络兼容

- 修复自定义 RH 节点查询 WebApp ID、提交、轮询、取消或上传时，由于上游请求手写 `Host` 而被 Chromium 系统网络栈本地拒绝的问题。
- RunningHub 国内/海外五条上游链路改为由目标 URL 自动生成 authority；共享 Chromium fetch 桥统一清理浏览器管理的 authority、连接和请求体分帧请求头，同时保留 Authorization、Content-Type 等 Provider 语义头。
- `http://127.0.0.1:18766/api/proxy/runninghub/*` 仍是桌面端前端访问本机安全后端的正常入口，真实 RunningHub 上游由后端决定，API Key 不暴露给渲染进程。
- Node stream/dispatcher 上传继续走 Node 网络栈并保留必要的 Content-Length；DNS 固定安全媒体传输的原始 socket Host 保持不变，不回退 v2.7.4 之后的系统代理、TUN、VPN、IPv4/IPv6 和安全下载能力。
